# 管理端全局主题与签到大屏重构设计

日期：2026-08-21  
状态：用户已确认

## 1. 目标

统一管理端界面外观，为项目列表、项目工作台、设置抽屉、个人中心和签到大屏提供浅色/深色双主题；同时重构签到大屏标题、签到控制和二维码入口，解决按钮风格混乱、二维码重复占位和内容向下溢出的问题。

## 2. 范围

主题覆盖：

- 项目列表 `/projects`
- 项目工作台 `/project/:projectId`
- 个人信息 `/profile`
- 抽奖舞台内的管理设置抽屉
- 签到大屏 `/display`

主题不覆盖：

- 轮动抽奖舞台和转盘抽奖舞台的活动视觉主题
- 员工签到页 `/checkin`
- 工号入口 `/lottery/employee`
- 个人转盘 `/lottery/personal-wheel`

现有抽奖 `ThemeId` 用于舞台主题，不能复用为管理界面明暗模式，避免“活动配色”和“操作系统界面外观”相互污染。

## 3. 全局主题架构

### 3.1 状态模型

新增独立类型：

```ts
type UiAppearance = 'light' | 'dark';
```

新增 `UiAppearanceProvider`，在 `MainApp` 路由外层提供：

```ts
interface UiAppearanceContextValue {
  appearance: UiAppearance;
  setAppearance: (appearance: UiAppearance) => void;
  toggleAppearance: () => void;
}
```

存储键为 `luck_ui_appearance`。初始化优先级：

1. 浏览器已保存的用户选择。
2. 未保存时使用浅色主题。

本期不跟随 `prefers-color-scheme` 自动切换，避免大屏运行期间因系统计划任务突然变色。用户手动选择后即时生效，并在同一浏览器后续访问中保持。

### 3.2 主题作用域

管理页面根节点使用：

```tsx
<div className="admin-ui" data-ui-theme={appearance}>
```

CSS 变量只在 `.admin-ui` 作用域内定义。设置抽屉从抽奖舞台打开时，自身根节点也挂载 `.admin-ui`，因此只改变抽屉，不改变下方开奖舞台。

核心变量：

```css
--ui-bg;
--ui-surface;
--ui-surface-raised;
--ui-border;
--ui-text;
--ui-text-muted;
--ui-primary;
--ui-primary-soft;
--ui-danger;
--ui-success;
--ui-shadow;
```

浅色保持冰蓝灰背景、白色卡片和品牌蓝；深色使用深蓝黑背景、蓝灰卡片和高对比文字。绿色只用于数据库连接、签到成功等语义状态。

### 3.3 切换入口

- 签到大屏顶部工具组提供太阳/月亮按钮。
- 设置抽屉标题栏提供相同按钮。
- 两个入口读取同一 Context，切换后全局管理页面立即同步。
- 按钮具备明确的 `aria-label`，分别为“切换到深色主题”和“切换到浅色主题”。

## 4. 签到大屏信息架构

### 4.1 顶部栏

顶部栏分为左右两区，并允许在较窄屏幕换行：

```text
返回  活动名称
      签到大屏 · 数据库已连接        [签到状态/倒计时] [时间] [刷新][声音][主题][二维码][全屏]
```

标题层级：

- 主标题只突出活动名称。
- “签到大屏”作为小型页面标签，不再与活动名使用同等字号。
- 数据库连接状态使用小圆点和短文本，不使用大面积绿色。

签到控制：

- 未开始：品牌蓝主按钮“开始签到”。
- 进行中：中性状态胶囊显示倒计时或“签到进行中”。
- 结束：红色描边按钮“结束签到”，点击后出现确认，避免误操作。
- 剩余五分钟和一分钟分别使用橙色、红色语义提醒，但不持续大面积闪烁。

工具按钮全部使用相同尺寸、圆角、边框、悬停和按压反馈。图标按钮提供可访问名称和焦点环。

### 4.2 主体布局

桌面保持两栏：

- 左栏：实时签到动态，占剩余宽度。
- 右栏：签到进度、部门分布、刚刚签到，宽度约 360–384px。

删除右栏底部常驻二维码卡片。释放的空间交给“刚刚签到”和部门统计，主体在单个视口内完成布局，不再依赖被 `overflow-hidden` 截断的向下内容。

较窄屏幕改为可滚动单列，避免固定宽度导致横向拥挤；全屏大屏场景仍优先利用视口高度。

### 4.3 二维码弹层

二维码只有一个主入口：顶部工具组中的二维码按钮。

弹层内容：

- 白底黑码，保证扫描对比度。
- 活动名称和“扫码签到”说明。
- 复制链接按钮。
- 打开签到页按钮。
- 明确关闭按钮；点击遮罩或按 `Escape` 关闭。
- 签到进行中时可在弹层顶部显示剩余时间。

弹层外围背景随管理主题切换；二维码本体始终为白底黑码。

### 4.4 开始与结束签到

开始弹层继续提供 5、10、15、30、60 分钟和不限时选项，统一使用管理主题令牌。

结束签到增加确认状态：

- 文案明确说明结束后新扫码将无法签到。
- 取消不改变当前会话。
- 确认成功后状态切换为“未开始”，清空倒计时。
- 接口失败时保留进行中状态并展示错误，不制造前端假成功。

## 5. 组件边界

为避免继续扩大当前近千行页面，将视觉和交互拆分为小组件：

- `UiAppearanceProvider`：主题状态、持久化和切换。
- `AppearanceToggle`：复用的太阳/月亮切换按钮。
- `CheckInDisplayHeader`：标题、会话状态、时间和工具组。
- `CheckInQrModal`：二维码、复制、打开和关闭。

`CheckInDisplayPage` 保留数据加载、实时订阅、签到会话和统计状态；子组件通过显式 props 接收状态与回调，不直接访问 Supabase。

## 6. 错误处理

- 主题存储不可用：继续使用内存状态，不阻断页面。
- 复制链接失败：弹层显示错误反馈，不伪装“已复制”。
- 开始/结束签到失败：保留原状态并提供可重试反馈。
- 全屏 API 不可用或被拒绝：按钮保持可用，显示轻量错误提示。
- 数据刷新失败：保留现有数据，不清空签到动态。
- 二维码弹层关闭后恢复触发按钮焦点。

## 7. 可访问性与动效

- 图标按钮全部具备 `aria-label` 和可见焦点环。
- 弹层使用对话框语义，支持 `Escape` 和焦点管理。
- 主题切换后文字与背景满足 WCAG AA。
- 遵守 `prefers-reduced-motion`，禁用弹层位移、按钮缩放和签到庆祝弹跳，仅保留必要状态变化。

## 8. 测试与验收

单元/组件测试：

- 主题默认值、保存值恢复、切换和存储异常。
- 两个主题按钮共享同一状态。
- 签到大屏不存在常驻二维码卡片。
- 点击顶部二维码按钮打开弹层；复制、打开、关闭和 `Escape` 正常。
- 未开始/进行中/即将结束三种控制状态正确。
- 结束签到必须确认；失败时保持进行中。
- 浅色/深色根节点和关键令牌正确切换。

浏览器验收：

- 1440×900：主体无需向下寻找二维码，统计栏完整显示。
- 1024×768：顶部工具可换行且不重叠。
- 签到大屏切换深色后，打开设置抽屉显示相同主题。
- 设置抽屉切回浅色后，项目工作台和签到大屏同步恢复。
- 抽奖舞台外观不受管理主题影响。
- 二维码在浅色和深色下均可清晰扫描。

## 9. 与手机导航项目的关系

本设计与手机底部导航、个人中心和设置抽屉返回路径一并实施。`ProfilePage`、`MobileBottomNav` 和设置抽屉使用同一管理主题令牌；签到大屏仍不显示手机管理底部导航，以保持展示模式沉浸感。
