# 手机端底部导航与个人信息页设计

日期：2026-08-21  
状态：待用户确认

## 1. 背景与目标

当前项目工作台在手机端仍依赖顶部按钮完成项目切换、抽奖操作和账号管理，操作密度过高，也不符合移动端以拇指触达为主的交互习惯。

本次设计为已登录的管理端增加固定底部导航，提供三个稳定入口：

1. 项目：浏览和管理所有项目。
2. 抽奖：返回当前或最近访问项目的抽奖工作台。
3. 我的：查看当前管理账号资料并退出登录。

桌面端继续使用现有顶部工作台，不显示底部导航。轮动抽奖舞台、转盘参与端、签到参与端和签到大屏等沉浸式页面不显示底部导航。

## 2. 信息架构

| 导航项 | 图标 | 默认路由 | 激活规则 |
| --- | --- | --- | --- |
| 项目 | `FolderKanban` | `/projects` | 当前路径为 `/projects` |
| 抽奖 | `Sparkles` | `/project/:projectId` | 当前路径为 `/project/:projectId` |
| 我的 | `CircleUserRound` | `/profile` | 当前路径为 `/profile` |

“抽奖”不是直接启动大屏开奖，而是进入项目工作台。这样可以避免误触直接打开演示舞台，并让管理员先检查签到人数、奖项和活动状态。

### 最近项目规则

- 每次成功打开 `/project/:projectId` 时，将项目 ID 写入本地键 `luck_last_project_id`。
- 项目列表页已经有项目数据时，优先使用最近项目；最近项目不存在时使用列表中的第一个项目。
- 个人信息页只读取本地最近项目 ID，不额外发起项目列表请求。
- 找不到可用项目时，“抽奖”点击后进入 `/projects`，由用户先创建或选择项目。
- 删除最近项目后，项目列表页清理失效 ID，并自动选择新的第一个项目作为回退。

## 3. 组件设计

### 3.1 `MobileBottomNav`

新增共享组件：`src/components/navigation/MobileBottomNav.tsx`。

建议接口：

```ts
type MobileNavSection = 'projects' | 'lottery' | 'profile';

interface MobileBottomNavProps {
  active: MobileNavSection;
  lotteryProjectId?: string | null;
}
```

组件职责：

- 生成三个导航目标和激活状态。
- 处理安全区和底部固定定位。
- 提供正确的 `aria-label`、`aria-current="page"` 和键盘焦点样式。
- 不读取数据库，不持有业务状态。

视觉规范：

- 仅在小于 `640px` 时显示。
- 高度为 `64px + env(safe-area-inset-bottom)`。
- 背景使用 88% 白色、16px 模糊和顶部浅边框。
- 每个入口最小触控区 44×44px。
- 未激活项使用 `#6b7280`；激活项使用品牌蓝 `#2563eb`。
- 激活项采用浅蓝圆角底板，不使用绿色、紫色或大面积渐变。
- 导航层级高于页面内容，低于确认弹窗和设置抽屉。

### 3.2 最近项目工具

新增 `src/utils/mobileNavigation.ts`，封装：

```ts
rememberLastProject(projectId: string): void
getLastProjectId(): string | null
clearLastProject(projectId?: string): void
resolveLotteryDestination(options): string
```

对 `localStorage` 的访问需要捕获浏览器隐私模式或存储不可用异常。

### 3.3 `ProfilePage`

新增受保护路由 `/profile`，页面文件为 `src/pages/ProfilePage.tsx`。

页面内容：

- 账号头像：使用姓名或邮箱首字母，不上传头像。
- 姓名：读取 `user_metadata.name`，为空时使用邮箱前缀。
- 邮箱：只读展示。
- 账号状态：已登录。
- 注册时间：读取 Supabase Auth 用户的 `created_at` 并本地化显示。
- 退出登录：使用红色文字的次级危险操作按钮；退出后返回 `/login`。

本期不提供修改邮箱、修改密码、上传头像或删除账号，避免引入验证邮件和高风险账号操作。

## 4. 页面集成

### 项目列表 `/projects`

- 底部导航激活“项目”。
- 内容底部增加导航占位，避免最后一张项目卡被遮挡。
- 项目加载完成后计算“抽奖”入口的回退项目。
- 删除项目时同步清理最近项目记录。

### 项目工作台 `/project/:projectId`

- 底部导航激活“抽奖”。
- 项目加载成功后记录当前项目 ID。
- 手机端顶部只保留返回、项目名称和模式标签。
- 手机端隐藏“设置 / 大屏开奖 / 签到一览”顶部按钮；这些功能继续保留在页面下方操作卡中。
- 内容底部增加底部导航高度与安全区间距。

### 个人信息 `/profile`

- 底部导航激活“我的”。
- 使用与项目页一致的浅色背景、16px 卡片和品牌蓝。
- 加载用户失败时显示可重试状态；会话失效时由现有 `RequireAuth` 跳转登录。

## 5. 状态与交互

- 页面切换使用 React Router，不刷新页面。
- 导航点击采用 80–150ms 按压反馈。
- 激活状态只由当前路由决定，避免出现两个同时激活的入口。
- 底部导航不在输入框聚焦时自动隐藏，以保持稳定导航；页面使用 `scroll-padding-bottom` 防止字段和按钮被遮挡。
- 设置抽屉、确认弹窗打开时覆盖底部导航，避免误触。
- 遵守 `prefers-reduced-motion`，关闭位移动画，仅保留即时颜色反馈。

## 6. 响应式与可访问性

- 手机：`<640px` 显示底部导航并简化工作台顶部操作。
- 平板和桌面：`>=640px` 隐藏底部导航，保持现有布局。
- 横屏手机仍显示底部导航，但压缩上下留白。
- 所有导航文字保持可见，不使用仅图标导航。
- 图标标记为装饰性，导航名称提供可访问名称。
- 焦点环使用品牌蓝，文字和背景满足 WCAG AA。

## 7. 错误处理

- 本地最近项目 ID 失效：回到项目列表，不显示空白页。
- Auth 用户资料请求失败：展示“重新加载”按钮，不退出当前会话。
- 退出登录失败：保留当前页面并显示错误提示。
- 项目列表为空：“抽奖”入口仍可点击，但进入项目列表的空状态，引导创建项目。

## 8. 测试与验收标准

### 单元测试

- 最近项目保存、读取、失效清理和回退路由。
- 三个路由对应唯一激活项。
- 无项目时抽奖入口回退 `/projects`。
- Profile 用户名称和邮箱回退规则。

### 组件测试

- 375px 下显示三个导航项；768px 和 1440px 下隐藏。
- 当前页面具有 `aria-current="page"`。
- 个人信息页加载、错误和退出状态。

### 浏览器验收

- 375×812：导航不遮挡项目卡、操作卡和退出按钮。
- 768×1024、1440×900：现有桌面导航无回归。
- iPhone 安全区：底部内容不贴近 Home Indicator。
- 项目 → 抽奖 → 我的可连续切换，浏览器返回行为正确。
- 轮动抽奖舞台和签到参与页不出现管理端底部导航。

## 9. 实施边界

本次只实现管理端手机导航、最近项目记忆和只读个人信息页。不会修改数据库结构、Supabase Auth 策略、轮动抽奖舞台样式或参与者端业务流程。
