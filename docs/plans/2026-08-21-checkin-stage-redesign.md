# 签到大屏舞台化重设计

## 目标

签到大屏不再沿用通用后台的左右卡片堆叠。页面作为活动现场的公共显示界面，应在一屏内优先呈现“谁刚刚签到、整体签到进度、部门分布与会话状态”，并在签到人数很少时仍保持完整、平衡的构图。

## 视觉方向

- 浅色模式遵循设计文档的 Apple 极简语言：冷白背景、微透明玻璃、1px 冷灰边框、克制阴影。
- 深色模式恢复 Git 原版签到页的沉浸舞台：`#0b0a1a` 深蓝黑底，蓝、靛紫、品红三层低透明柔光，并叠加极轻网格。
- 字体使用 SF Pro / 苹方字体栈；倒计时、时钟、比例数字使用 SF Mono 与 `tabular-nums`。
- 绿色仅表达“数据库已连接 / 已签到”等成功语义，品牌强调统一使用科技蓝与靛紫。

## 布局

- 顶部为单一玻璃控制台：活动标题、连接状态、会话倒计时与工具按钮处于同一基线。
- 主体采用 12 栏舞台栅格。左侧 7 栏为“最新签到焦点舞台”，首位签到者以大头像、姓名、部门、工号和时间呈现；其余签到者进入下方紧凑时间线。
- 右侧 5 栏为“数据指挥区”，使用环形签到率、人数拆分、最后签到时间和部门分布，避免重复的“刚刚签到”卡片。
- 小屏自动切为单列，控制台允许横向换行，所有按钮保持至少 44px 热区。

## 数据与交互

沿用现有 Supabase 查询、Realtime 订阅、签到队列、开始/结束会话、二维码和声音逻辑。只调整展示组件与主题变量，不改变数据库结构和业务行为。新签到仍显示全屏欢迎动画，但视觉统一为蓝紫舞台语言。

## 验收

- 1321×1008、1440×900、390×844 下无横向溢出，主要内容不出现无意义大片空白。
- 浅色与深色均满足正文对比度，深色风格与 Git 原版舞台氛围一致。
- 现有组件测试、TypeScript 类型检查和生产构建全部通过。
